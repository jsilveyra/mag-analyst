Fix: "Cannot access method 'createCallbackFcn'" crash on startup

My mistake in the last extraction: createCallbackFcn is a protected method of MATLAB's matlab.apps.AppBase class (verified directly against the class metadata) — it can only be called from within the app class itself, never from a separate class like PlaygroundUtils, even when app is passed in as an argument. I'd moved all three table-configuration methods' bodies wholesale into PlaygroundUtils.m, including the one line in each that wires up the table's CellEditCallback — that line has to stay behind on the app class.

src/Playground/PlaygroundUtils.m is already fixed directly (removed the createCallbackFcn line from all three methods there, no port needed for that file). The three delegators below now do two things instead of one: call into PlaygroundUtils for everything else, then wire the callback themselves.

Everything else from the last guide (all 36 edits) checked out perfectly — every delegator landed as a clean thin wrapper, no duplicates, structurally balanced. This was the only bug.

Step 1. configure_minor_loop_table

Find this in Code View
        function configure_minor_loop_table(app)
            PlaygroundUtils.configure_minor_loop_table(app);
        end
Replace with
        function configure_minor_loop_table(app)
            PlaygroundUtils.configure_minor_loop_table(app);
            if isprop(app, 'UITable') && ~isempty(app.UITable) && isvalid(app.UITable)
                app.UITable.CellEditCallback = createCallbackFcn(app, @UITableCellEdit, true);
            end
        end
