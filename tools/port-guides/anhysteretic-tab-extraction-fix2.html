Fix: properties block needs to be public for AnhystereticUtils to reach it

Root cause of No public property 'number_components' for class 'app': MATLAB's class access control means a separate class like AnhystereticUtils cannot read or write another class's Access = private properties — not even when it's handed the object as an argument. PlaygroundUtils never hit this because it only ever touches UI components (which are all public), never this custom state block.

AnhystereticUtils.m's extracted methods (init_components, calculate_parameters, fit_parameters, the plot methods, etc.) read and write 14 of the properties in this block: Colors, Hcr, Hx, component_row_types, data_curve, fitted_parameter_values, lb, magnetic_parameters, mcr, modeled_curve, number_components, select_fit, stop_fit_requested, ub. Rather than widen access one property at a time (and hit the same wall again for Hysteretic/Input in a future session, since those tabs share several of the same properties — data_curve, Hcr/mcr/Hx, magnetic_parameters, stop_fit_requested), the simplest robust fix is to make the whole block public — it's a pure widening (nothing currently depends on these being private), and it matches every other property in this class (the UI components in the block above are already all public).

Step 1. Change the second properties block from private to public

Find this in Code View (right after the UI-components properties block, which ends with "Menu2")
    properties (Access = private)
        AppRoot string                % MOD: root folder of the app
This is the SECOND properties block in the file (custom app state — Hcr, mcr, data_curve, etc.), not the first one at the top of the file (UI components, already public). Make sure you're changing the right one.
Replace with
    properties (Access = public)
        AppRoot string                % MOD: root folder of the app
