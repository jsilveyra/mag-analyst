Hysteretic-tab precision fields — Stage 1

What this fixes: after a JA fit, fit_ja_parameters was writing the optimized Ms/a/alpha/c/k back into the tab's edit fields as a fixed 4-decimal string (format_short). For small values — alpha especially, typically ~1e-3 to 1e-6 — this rounds to the literal string "0.0000", and since these fields had no separate full-precision storage, that truncated string silently became the stored value. Every later read (a re-fit, Playground) then used a corrupted, effectively-zero alpha. That's the "worse than the seed" result you saw on MnZn_ferrite.

The fix converts these fields from plain text edit fields to Numeric Edit Fields. Numeric edit fields store the exact double in .Value no matter what — ValueDisplayFormat only controls the at-rest display — and MATLAB automatically shows full precision the moment you click in to edit, with no custom code needed. This is the only field type in your MATLAB version with a focus-aware display (plain text/numeric-text edit fields have no focus callback at all, so this is the one and only way to get the "click reveals everything" behavior you described, matching m_i(Hcr_i)'s behavior on the Anhysteretic tab).

Scope of this stage: the 7 Hysteretic-tab value fields (Ms, a, alpha, c, k, and the read-only Htip/Mtip tip display) plus their 10 bound fields — 17 fields total, all in GridLayout2. Playground's copies of these fields and the Anhysteretic table's Hcr/Hx rows are deferred to follow-up passes.

Trade-off accepted: these fields lose the comma thousands-grouping format_short used to add (e.g. 750,000 becomes 750000).

Part A — Design View: recreate 17 fields as Numeric Edit Fields

Component type can't be changed from Code View — App Designer's Design View is the source of truth for it. First, check whether your App Designer version has a faster path: right-click the field in the Component Browser and look for a "Convert to" / "Change type" option. If that exists, use it and just set the properties from the table below. If not, use this generic recipe for each of the 17 fields listed in the table:

  1. In the Component Browser, select the old field (e.g. JsField_2) and note its Row/Column (Layout section of the Inspector) — cross-check against the table below, they should match.
  2. Delete the old field.
  3. From the component palette, drag a Numeric Edit Field into the same grid cell (same row/column) inside GridLayout2 (the Hysteretic tab's grid — the same grid all the other JA-fitting controls live in).
  4. In the Component Browser, rename the new field back to the exact original name (e.g. JsField_2) — double-click the name or use the rename option. This is what keeps every method in app_exported.m working unchanged; the class property name doesn't change, only the underlying widget type does.
  5. In the Inspector, set Layout.Row / Layout.Column to match the table, HorizontalAlignment = right, Editable, AllowEmpty, and ValueDisplayFormat per the table below.
  6. Leave Limits at its default [-Inf Inf] — don't restrict it; the existing validation code (e.g. Ms <= 0) keeps doing that job.

None of these 17 fields have any callback wired today (checked — no ValueChangedFcn on any of them), so there's no callback re-wiring to worry about.

Part B — Code View: 4 edits

These are ordinary Code View edits (not affected by the component-type change itself, just by the fact these fields' .Value is now always a plain double). Apply these in addition to Part A, then save — order between Part A and Part B doesn't matter as long as both are done before you try running the app.

Code edit 1. plot_input(app) — stop truncating the Hysteretic tip display before it's read back

JsField_7/JsField_8 become Numeric Edit Fields in this pass (see Design View section below), so these become plain numeric assignments — no more format_short() round-trip through a truncated string.

Find this in Code View
            app.JsField_7.Value = app.format_short(HTip);
            app.JsField_8.Value = app.format_short(MTip);
Replace with
            app.JsField_7.Value = HTip;
            app.JsField_8.Value = MTip;

Code edit 3. Project load — read Ms/a/alpha/c/k back as numbers, not text

str2double(string(...)) works whether s.params.Ms came from an OLD project file (saved as a JSON string) or a NEW one (saved as a JSON number, now that these fields are numeric) — backward compatible with project files saved before this change.

Find this in Code View
                if isfield(s.params, 'Ms'); app.JsField_2.Value = char(string(s.params.Ms)); end
                if isfield(s.params, 'a'); app.JsField_3.Value = char(string(s.params.a)); end
                if isfield(s.params, 'alpha'); app.JsField_4.Value = char(string(s.params.alpha)); end
                if isfield(s.params, 'c'); app.JsField_5.Value = char(string(s.params.c)); end
                if isfield(s.params, 'k'); app.JsField_6.Value = char(string(s.params.k)); end
Replace with
                if isfield(s.params, 'Ms'); app.JsField_2.Value = str2double(string(s.params.Ms)); end
                if isfield(s.params, 'a'); app.JsField_3.Value = str2double(string(s.params.a)); end
                if isfield(s.params, 'alpha'); app.JsField_4.Value = str2double(string(s.params.alpha)); end
