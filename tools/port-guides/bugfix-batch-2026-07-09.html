Step 2. calculate_plot_and_refresh_hysteretic(app)

Location in current app_exported.m: ~line 751 (App Designer Code View)

This is the handler behind the Anhysteretic tab's own "Calculate & Plot" button. With no dataset imported, app.data_curve is still [], and plot(app) would crash partway through drawing the first (M) axes — after cla(ax,'reset') had already wiped its box/frame back to figure defaults, which is why only the first plot visibly lost its right/top frame and y-axis (the crash happens before the other two axes are touched). This guard stops before any of that runs and shows a clear message instead.

Anchor / Before
        function calculate_plot_and_refresh_hysteretic(app)
            update_components(app)
            calculate_parameters(app)
            plot(app)
After
        function calculate_plot_and_refresh_hysteretic(app)
            if ~isobject(app.data_curve) || ~isprop(app.data_curve, 'H') || isempty(app.data_curve.H)
                app.write_message("No dataset imported yet. Please import a dataset on the Input data tab first.");
                return;
            end
            update_components(app)
            calculate_parameters(app)
            plot(app)

Step 3. startupFcn — apply the Anhysteretic tab's grid checkboxes at launch

Location in current app_exported.m: ~line 981-982, inside startupFcn (App Designer Code View)

The Anhysteretic tab's three "Grid" checkboxes (ShowgridCheckBoxM, ...dMdH, ...HdMdH) already default to checked, but the grid was only ever actually drawn on the axes from each checkbox's own ValueChanged callback — never at startup. That's why the grid looked off until the user toggled a checkbox (or ran Calculate & Plot, which redraws the axes from scratch and does apply it). This mirrors the fix already in place for AxesM_2 (Hysteretic tab) and AxesM_5 (Harmonics playground) just below it.

Anchor / Before
            app.sync_hysteretic_fitting_ui();
            app.apply_detailed_grid(app.AxesM_2, app.ShowgridCheckBoxM_2.Value == 1);   % MOD: grid checkbox defaults to checked but was never applied until Calculate&Plot
After
            app.sync_hysteretic_fitting_ui();
            app.apply_detailed_grid(app.AxesM, app.ShowgridCheckBoxM.Value == 1);   % MOD: grid checkbox defaults to checked but was never applied until Calculate&Plot
            app.apply_detailed_grid(app.AxesdMdH, app.ShowgridCheckBoxdMdH.Value == 1);   % MOD: grid checkbox defaults to checked but was never applied until Calculate&Plot
            app.apply_detailed_grid(app.AxesHdMdH, app.ShowgridCheckBoxHdMdH.Value == 1);   % MOD: grid checkbox defaults to checked but was never applied until Calculate&Plot
            app.apply_detailed_grid(app.AxesM_2, app.ShowgridCheckBoxM_2.Value == 1);   % MOD: grid checkbox defaults to checked but was never applied until Calculate&Plot

Step 4. CalculatePlotButton_2Pushed — fix the malformed "was not found" message

Location in current app_exported.m: ~line 1520-1530, Hysteretic tab's "Calculate & Plot" button (App Designer Code View)

When app.InputDatasetPath.Value is empty (nothing browsed yet), the old message read " was not found, please browse the dataseth path again" — no subject before "was not found", and "dataseth" is a typo for "dataset". The new shared helper (Step 1) handles both the empty-path case and the typo.

Anchor / Before
                app.import_data(path);
                app.plot_hysteretic_tab_data();
                app.update_hysteretic_error_display();
            else
                app.write_message(path + " was not found, please browse the dataseth path again");
            end
After
                app.import_data(path);
                app.plot_hysteretic_tab_data();
                app.update_hysteretic_error_display();
            else
                app.write_dataset_not_found_message(path);
            end

Step 6. startupFcn — unify the version string

Location in current app_exported.m: ~line 1014, inside startupFcn (App Designer Code View)

The startup message hardcoded a stale "1.0.3-beta" while the splash screen (MagAnalyst.m) said "2.0.0" and the App Designer Sharing-details metadata said "1.0" — three different numbers for one app. All three now read from a single new file, AppVersion.m (repo root, next to app.mlapp), currently returning "2.0" (MATLAB's Sharing Details field only accepts MAJOR.MINOR, no third component).

⚠️ Step 6b (Design View, not Code View — do this too): App Designer → Share button → Sharing Details… → set Version to 2.0. This metadata lives in the .mlapp package outside Code View and isn't reachable from MATLAB source, so it can't be wired to AppVersion.m automatically — as of this guide it is still showing the old "1.0" and needs this manual update. See CLAUDE.md §9 for the policy on bumping this alongside AppVersion.m.
Anchor / Before
            app.write_message("MagAnalyst 1.0.3-beta");
After
            app.write_message("MagAnalyst " + AppVersion());
